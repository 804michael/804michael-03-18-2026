1Paste the MLS export

Any CSV with a header row. Columns are matched by name, so the export does not have to be in a particular order — extra columns are ignored and missing ones just leave blanks.

Nothing leaves this page. The paste is read in your browser and held in memory only — it is never uploaded, never saved to the server, and never written into the site's code. It is gone when you close the tab. That matters because this repository is public and MLS data is licensed.

2The stops on your tour

One address per line — in the real thing these come straight from the planner. Typed loosely on purpose here, to show the matching cope with it.

Green marks the best number in each row. This is the drive-home view — the one that answers "which of these was the better buy".

Rough monthly cost, so "what would that run me a month?" has an answer at the kerb instead of a promise to check later.

Tax rate per $100 of value

These rates are starting points, not gospel. Localities set them every year and they move. Check each one against the county or city website and correct it here before the number goes anywhere near a client — the figures are yours to maintain, saved in this browser.

The same stops as the client's phone would show them. Everything held back is listed underneath, so what crosses the line is a decision rather than an accident.

EErrand runs

A different job from a home tour: twenty-odd stops, no client, and Google will not take them in one link. Google Maps accepts nine waypoints per link, which is exactly why the planner caps a tour at ten stops. Splitting an optimised order into runs is how you get past that without giving up the order.

Where the split belongs. After optimising, not before, and as contiguous chunks of the optimised order — a good route does not jump around, so a slice of one is already geographically tidy. The alternative (cluster first, optimise each cluster) only wins when the runs are separate trips on different days that each start from home. If that becomes the real use, the base toggle above is the switch that should trigger it.

What this prototype does not do. It groups the order you give it. The optimiser lives in the planner and already works — this is only the half that is new, so the two can be judged separately.

Read me before this goes anywhere near a client

Agent-only fields must never reach the client page. An MLS export carries buyer-agent names and phones, seller-paid closing costs, days on market, showing instructions, lockbox details and agent remarks. This prototype keeps them behind an allow-list, the same way /api/tour-page does for the tour itself — the client page renders only what is explicitly permitted, never "everything except".

Publishing listing facts is a licensing question, not a technical one. Beds, baths, square feet and list price are MLS content. Sending them to a named client in a private link is one thing; putting them on a public URL is another, even a noindex one. Worth one email to CVR MLS before the client-facing half is switched on. The agent-facing half — this page, Tour Mode, the printed agent copy — raises none of that.

A pasted CSV is a snapshot. It is right on the morning you export it and wrong the moment a price changes. Anything shown to a client should carry the date it was pulled.
